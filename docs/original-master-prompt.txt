> # PROJECT
> **Secure Media Assurance Platform**  
> **Integrated Secure Data Erasure + Advanced File Recovery**
>
> The platform has three pillars:
>
> 1. **Sanitization** — securely erase an entire test media image or selected files/folders using the correct media-aware method.
> 2. **Forensics** — recover deleted/damaged files from uploaded forensic disk images in read-only mode.
> 3. **Assurance** — prove who performed each action, on which device/case, when it happened, what result was produced, and whether audit records were modified.
>
> This is an **SIH prototype**, so it must be fully demonstrable through a hosted link. Do not pretend a hosted browser can directly erase the visitor’s physical HDD/SSD. For the deployable prototype, perform real operations on **uploaded files, uploaded test disk images, server-side sandbox copies, and provided demo datasets**. Create a clean adapter interface for future native HDD/SSD/NVMe execution through a local privileged agent, but clearly label physical-device commands as “Local Agent / Future Deployment” unless actually connected.
>

> # 8. ADVERSARIAL SANITIZATION VALIDATION
>
> This is another core differentiator.
>
> After sanitization:
>
> `Sanitize → Normal verification → Recovery engine challenges sanitized media → Artifact detection → PASS / WARNING / INCONCLUSIVE`
>
> Reuse the recovery engine.
>
> Search for supported residual artifacts.
>
> Results:
>
> **PASS**
> - no supported recoverable artifacts detected
>
> **WARNING**
> - recoverable artifacts detected
>
> **INCONCLUSIVE**
> - validation cannot determine confidently
>
> Do not claim absolute physical erasure.
>
> Use wording:
>
> **“No recoverable supported artifacts were detected by the implemented validation methods.”**
>
> Store this result in the case and audit record.

> # 11. TAMPER-EVIDENT AUDIT LOG
>
> Every event must be part of a SHA-256 hash chain.
>
> For every event:
>
> `current_hash = SHA256(previous_hash + canonical_event_payload)`
>
> Store:
>
> - previous hash
> - current hash
>
> Create a backend endpoint:
>
> `POST /audit/verify`
>
> It must recompute the chain and return:
>
> - VALID
> - BROKEN
> - first invalid event
>
> Create an admin/demo page allowing a safe demonstration:
>
> - show original audit chain
> - intentionally modify a copy of one event
> - rerun verification
> - show **TAMPERING DETECTED**
